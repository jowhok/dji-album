## 本轮交付：v0.1.3（白线根治打包 + 文档整理 + 代码上传 GitHub）

### 照片放大白线根治（v0.1.2 之后完成，本轮首次进包）
v0.1.2 打包后用户反馈「放大到某些百分比仍有白线」。根因：非 none 的 `transform` 会把 8K 大图提升为合成层，Chromium 分块栅格化的 256px tile 接缝在放大后透出浅色背景，形成等间距横线。**最终彻底不用 transform**，照片缩放改走 `width/height + left/top` 普通布局属性（`Player.tsx` 用 `natural` + 视口算出 `fit`/`baseW`/`baseH`，`clampPan` 按 baseW/baseH 钳边界），并删掉 `.player-photo` 的 `will-change: transform` / `transform-origin`。缓存图 `onLoad` 早于 React 绑定导致 `natural=0` 的问题，用 effect 主动同步 DOM 尺寸 + load 双保险修掉。开发态照片回归 25/25。**注意：v0.1.2 的 exe 不含此修复，v0.1.3 是第一个带白线根治的正式包。**

（同期还有 `.tile` 的 `content-visibility: auto` 导致卡片全空的问题，已删除该 CSS，只保留分批渲染。）

## 上轮交付：v0.1.1（照片缩放拖动 + 缩略图加载加速）

两个需求：① 照片预览支持鼠标滚轮缩放、左键拖动；② 用户反馈缩略图要近一分钟才出来，排查是读取问题还是 NAS 慢。

### 照片预览缩放 / 拖动
- 图片外包 `.photo-viewport`，`<img>` 用 `transform: translate(x,y) scale(zoom)`，viewport `overflow:hidden` 裁剪；右下角显示倍率浮标。
- **滚轮**：React 的 `onWheel` 是 passive 监听（`preventDefault` 无效），改用原生 `addEventListener('wheel', ..., {passive:false})`；指数缩放 1~8 倍，**以鼠标位置为锚点**（`x' = m - ratio*(m-x)`）；缩回 1 倍自动回中。
- **拖动**：`pointerdown/move/up` + `setPointerCapture`，左键拖动平移；`clampPan` 按图片实际渲染尺寸限制边界（未超出视口时不可拖）；双击复位；切媒体由 `key={path}` 自动回到 100%。
- **兼容**：右键菜单、上/下一个大箭头（`z-index:3`）、点击外部关闭、视频模式全部不受影响；图片模式底部提示改为「滚轮 缩放 · 左键拖动 · 双击复位」。
- **边界修复**：`clampPan` 在图片尚未解码（`offsetWidth=0`）时会把平移钳成 0，改用 `naturalWidth` 判断并以视口尺寸兜底。

### 缩略图加载慢（明确不是 NAS 慢）
诊断：本地缓存 369 个 JPG 全部存在、`thumbMissing=0`；Node 直连 media server 实测 **200 并发 366ms / 6 连接 226ms**；CDP `performance` 却显示每个 `/thumb/` 请求耗时 **85984~86052ms** 且几乎同时开始/结束 → 浏览器端请求集体挂起。Network 域复测 reload 后 369 个请求 3 秒内完成、单请求 ≤1ms，确认为**原生 `loading="lazy"` 在启动/窗口非前台时被 Chromium 节流**。
修复：
- `Timeline.tsx` 去掉 `loading="lazy"` → 立即加载 + `decoding="async"`（本地 360px 小图共约 8MB，全量并发约 4 秒内完成，不再受可见性节流）
- `media-server.ts` `/thumb/` 补 `Content-Length`（原来 chunked）、HEAD 支持与 stream error 兜底
- 新增 `scripts/check-thumbs.mjs` **7/7**：响应头无 chunked、图片非 lazy、冷加载 369 张 <10 秒、0 破损、数据不污染

### 回归脚本基线动态化
用户 NAS 数据已变为 **369 媒体 / 107 视频 / 262 照片 / 2 收藏**（原 318/100/218/0），全套脚本写死 318 导致大面积误报。统一改为 `DJI_TILES` / `DJI_FAV` 环境变量常量；视频断言改为**明确选带 `.tile-play` 的卡片**（新数据首张是照片）；收藏断言改为 `FAV` / `FAV+1`；真实鼠标点击前 `scrollIntoView`（卡片滚出视口会静默失效）。

**验证**：typecheck ✓ build ✓ **全套 12 个脚本全绿**：check-thumbs 7/7、check-photo-zoom 25/25、check-settings 34/34、check-player-ui 22/22、check-player-popup 24/24、check-player / check-m6 / check-features / check-views / check-purge ALL PASS、check-contextmenu 11/11、check-release 10/10（每个脚本前刷到干净页面）✓ 收尾 `files=369 / fav=2 / trash=0 / 缓存 369 个 8.1MB / 待生成 0 / 主题 light` ✓ 版本升 0.1.1 并完成打包交付（详见下节）。

## 本轮修复：右键菜单真实鼠标触发不了

**现象**：M6 交付后所有 CDP 脚本全绿，但真实右键点卡片完全不出菜单。

**根因（CDP 事件探针实测）**：`ContextMenu.tsx` 在 `useEffect` 里同时注册了 `window` 的 `mousedown` 与 `contextmenu` 监听来「点外部关闭」。真实右键序列是 `mousedown(button=2) → contextmenu → mouseup`；React 18 对真实离散事件会同步刷新 effect，于是**打开菜单的那一次 `contextmenu` 冒泡到 window 时，刚挂载的组件自己的监听器立刻把自己关掉**：

| t(ms) | 事件 |
|---|---|
| 12 | `contextmenu`（isTrusted=true）→ `onMenu` 打开菜单 |
| 15 | `.ctx-menu` 挂载（MutationObserver `menu:true`） |
| 15 | `contextmenu` 冒泡到 window → `outside` 触发 `onClose()` |
| 17 | `.ctx-menu` 卸载（`menu:false`）→ 菜单只活了 2ms |

旧验证脚本全部在 `Runtime.evaluate` 里 `dispatchEvent(new MouseEvent('contextmenu'))` 合成事件，不走这条同步 effect 路径，所以一直 ALL PASS —— 典型「自动化绿、真人点不了」。

**修复**：移除 `window` 的 `contextmenu` 监听（含对应 remove），只保留 `mousedown` / Escape / resize / 容器滚动关闭，并在代码里留注释防止改回去。在别处右键时 `mousedown` 先关旧菜单，再由新卡片的 `contextmenu` 打开新菜单，行为正确。

**新增真实输入回归 `scripts/check-contextmenu.mjs`**：用 CDP `Input.dispatchMouseEvent` 发真实 `mousePressed(right)` / `mouseReleased(right)`，覆盖第一次右键、菜单已开时第二次右键、600ms 稳定可见、点击菜单项执行动作、点击外部关闭且不误开播放器、Escape 关闭、合成完整序列兜底 —— **11/11 PASS**。另有 `scripts/probe-ctx-events.mjs` 保留事件序列探针（`isTrusted` / 时序 / MutationObserver）。

**验证与收尾**：typecheck ✓ build ✓ 真实输入 11/11 ✓ `check-m6` 31/31 ✓ `check-features` / `check-views` 在干净页面重跑 ALL PASS ✓ `files=318 / fav=0 / trash=0` ✓ 已重启为无调试端口的正式窗口（`MainWindowTitle: DJI 相册`，句柄非 0）。

> 备注：`check-features` / `check-views` 连续跑时会因上一脚本遗留的菜单/收藏状态误报 4 项红，与本次改动无关；reload 到干净页面后全绿。新回归脚本结尾已加 Escape 清理、外部点击改到左下角空白区避开卡片，避免再污染后续脚本。

## 已知限制
- **合成事件不能验证真实交互**：旧 CDP 脚本用 `dispatchEvent` 派发 `contextmenu`，绕过了 React 18 离散事件的同步 effect 路径，才漏掉了本次 bug；涉及真实输入的回归一律用 `Input.dispatchMouseEvent`（见 `check-contextmenu.mjs`）
- **F11 未做自动化断言**：主进程 `before-input-event` 捕获真实键盘，CDP 注入的按键不经过该管线；按钮路径已硬验证，F11 需真实键盘确认
- **彻底删除未在真实 NAS 上执行验证**（安全考虑，只在临时目录单测真实删除）；首次点击「永久删除」即为真实删除，请核对清单
- **下载功能未做自动化验证**：会弹出系统原生「另存为」对话框，需在窗口里手动点一次确认
- 播放走 WiFi 读 NAS：LRF 代理约 5~7 Mbps 流畅；切 MP4 高清（30~50 Mbps、4K 10-bit）在无线下可能卡顿
- 首次元数据提取按文件数计约 20 秒 / 318 个（只读文件头），之后增量跳过
- 回归脚本基线用 `DJI_TILES` / `DJI_FAV` 环境变量控制，NAS 增减文件或收藏变化后重新设置即可
- 窗口由后台任务托管，约 10 分钟后自动关闭；长期使用请自己双击 `release/v0.1.3/DJI 相册-Portable-0.1.3.exe` 或安装 Setup 版
- **exe 未做代码签名**：首次运行 Windows SmartScreen 可能提示「未知发布者」，点「更多信息 → 仍要运行」即可；本机自用不影响
- 便携版为自解压单文件，启动约 15~20 秒才出现窗口；安装版启动更快
